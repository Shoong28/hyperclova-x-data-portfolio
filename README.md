# 오승은 | LLM 데이터 구축·평가 포트폴리오

**도메인에 필요한 데이터를 설계하고, 합성·정제·검수를 거쳐 모델 성능으로 확인하는 개발자입니다.**

## 01 · 의약품 도메인 LLM 평가 연구

**원천 데이터 선별 → 합성 문항 생성 → 품질 정제 → 다면 평가**

2025.07–2025.11 · **2025 디지털 바이오헬스 종합설계 경진대회 심사위원상**

의약품 지식을 단일 객관식 점수로만 평가하지 않기 위해, 서로 다른 판단을 요구하는 6개 문항 유형을 구성했습니다.

- **정보 충실도를 기준으로 원천 데이터 선별:** DrugBank의 7개 필드 중 약물명을 포함해 최소 5개가 채워진 218개 의약품을 선택했습니다.
- **합성과 규칙 기반 변환 결합:** GPT-4.1로 MCQ 2,180개를 생성하고 부적절한 텍스트 5개를 제거했습니다. 변환 실패 153개를 제외한 2,022개를 대체 유형 구성에 활용했습니다.
- **목적에 맞는 타겟 문항 추가:** 기존 MCQ·MAQ·RQ·TFQ에 임상 맥락 판단(TFQ2)과 처방 적절성 판단(TFQ3)을 추가 설계했습니다.
- **평가 단위와 오류 구분:** 전체 응답 기준 Strict Accuracy와 파서가 유효하다고 판단한 응답의 Precision·Recall·F1을 함께 분석했습니다. MAQ는 선지별, RQ는 판단·정답 선택별로 분해했습니다.

| 프롬프트 | 평균 Strict Accuracy |
|:--|--:|
| Answer-only | 75.80% |
| Chain-of-Thought | 82.17% |
| Chain-of-Verification | 81.50% |

추가 검증 단계가 항상 성능을 높이지는 않았습니다. 문항 유형과 출력 형식까지 함께 살펴야 오류 원인을 해석할 수 있었습니다. 이 연구는 **합성 평가 데이터와 추론 조건 비교** 경험이며, 학습 데이터 조성을 바꾼 ablation 학습 실험과는 구분합니다.

`Python` `pandas` `OpenAI API` `LangChain` `PyTorch` `Transformers` `scikit-learn`

## 02 · 수학 서술형 채점 데이터 구축·모델 개선

**모델 초안의 직접 검수 → 파인튜닝 데이터 구성 → 정답·근거 평가 → 오류 분석**

2025.03–2025.10 · 3인 졸업프로젝트 · **A+** · JIIS 논문 투고·심사 진행 중(2026.09 기록 기준)

문항 생성·검증부터 채점·피드백까지 이어지는 팀 프로젝트에서, 저는 채점 기준 생성·부분점수 채점·피드백 및 평가 파이프라인을 맡았습니다.

- **도메인 기준의 구조화:** 교육과정 성취기준을 특정 풀이 순서에 종속되지 않는 루브릭과 배점으로 변환했습니다.
- **검수된 데이터 구축:** 모델 초안을 검수·수정한 채점 기준 예제 50건, 학생 답안과 모범 채점 결과로 구성한 파인튜닝 데이터 538건을 만들었습니다.
- **평가 데이터 설계:** 9개 단원 × 10문제 × 정답·오답 답안 각 2개로 평가 답안 360건을 구성했습니다.
- **모델 개선과 오류 분석:** 프롬프트·파인튜닝을 비교하고, o4-mini 기반 Judge로 근거를 검수했습니다. 연산·개념·풀이 흐름·오개념 식별·기준 적용의 5개 오류 유형을 분석했습니다.

채점 정확도는 **81.67% → 93.89%(+12.22%p)**, 근거 적절성은 **63.89% → 77.50%(+13.61%p)**였습니다. 프로젝트 기록의 개선 전후 수치이며, 데이터 규모나 특정 구성 요소 하나의 독립적인 기여도로 해석하지 않습니다. 근거 적절성은 LLM Judge 판정으로 사람 평가와 구분합니다.

`Python` `OpenAI API` `Fine-tuning` `Prompt Engineering` `LLM-as-a-Judge` `pandas`

## 데이터를 다루는 기준

1. **목표 능력에서 데이터 설계를 시작합니다.** 단일 정답, 복수 선택, 답변 검토, 임상 판단처럼 평가할 행동을 먼저 나눕니다.
2. **생성량과 품질을 함께 확인합니다.** 정보가 부족한 원천 표본, 부적절한 텍스트, 변환 실패를 구분해 정제합니다.
3. **최종 점수와 오류 원인을 함께 봅니다.** 출력 형식, 세부 판단, 채점 근거를 분리해 개선 지점을 찾습니다.
4. **실험이 보여주는 범위 안에서 결론을 냅니다.** 개선 전후 비교와 독립적인 요인 효과, 모델 판정과 사람 검수를 구분합니다.

앞으로는 이 경험을 학습 데이터 구성별 효과 검증으로 확장하고 싶습니다. 기준 데이터와 평가셋을 고정하고, 도메인·난이도·오류 유형별 데이터 구성을 바꾸어 ablation 학습으로 성능 기여도를 확인하는 과정에 기여하겠습니다.
